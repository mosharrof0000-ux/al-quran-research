# Instruction — PROJECT_WORK_LOG.md

**Instruction ID:** INST-PROJECT-WORK-LOG
**Target:** `PROJECT_WORK_LOG.md`
**Class:** A — Critical
**Status:** ACTIVE

## Purpose
Keep a chronological operational record of important work performed on the project.

## Rules
- Record what was done, why, affected files, verification, and resulting status.
- Do not use the work log as a substitute for current state or permanent architecture documentation.
- Important changes should reference versions/commits when available.
- Failed or reverted work should remain visible as history.
- Do not claim completion without verification.

## Dependencies
`PROJECT_STATE.md`, `PROJECT_CONTINUITY_PROTOCOL.md`, `INSTRUCTION_CHANGE_LOG.md`.

## Verification
Every significant work-log entry should be traceable to an actual project change or documented decision.

## Update Trigger
Any significant implementation, research, architecture, deployment, backup, or governance change.
