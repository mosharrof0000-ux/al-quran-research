# Project Agent Identity Registry

## Purpose
Every distinct project task receives a persistent Bengali human-like Agent Name and unique Agent ID. The identity follows the work through branch, commits, review, validation, deployment and handoff.

## Rules
1. A new distinct task gets a new Task ID and new Agent identity.
2. A continuation of unfinished work records the original Agent and the successor separately.
3. Agent identity is never erased from project history.
4. Branch names identify the agent/work category where practical.
5. Every task must leave a handoff record when paused, blocked or completed.
6. Names are labels for project accountability, not real-world human identities.

## Work chain
Task ID → Agent ID → Session ID → Branch → Files → Commit → Review → Validation → Deployment → Live verification → Notification → Handoff
