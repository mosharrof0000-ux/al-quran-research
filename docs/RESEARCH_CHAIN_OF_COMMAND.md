# গবেষণা-কাজের চেইন অব কমান্ড

**প্রকল্প:** আল-কুরআন ভাষাভিত্তিক গবেষণা  
**নথির ধরন:** স্থায়ী কাজ, চিন্তা, সিদ্ধান্ত ও পরিবর্তনের ধারাবাহিক রেকর্ড  
**প্রাথমিক সংস্করণ:** 0.1

---

## ১. উদ্দেশ্য

এই নথির উদ্দেশ্য হলো একটি চিন্তা থেকে শুরু করে তার প্রশ্ন, সিদ্ধান্ত, নির্দেশ, বাস্তব কাজ, পরীক্ষা, ফলাফল, সংশোধন এবং পরবর্তী কাজ পর্যন্ত সম্পূর্ণ ধারাবাহিকতা সংরক্ষণ করা।

আমরা শুধু কী তৈরি করেছি তা সংরক্ষণ করব না; কেন করেছি, কীভাবে করেছি এবং পরীক্ষায় কী পাওয়া গেছে—সেটিও সংরক্ষণ করব।

এটি কোনো AI-এর গোপন Chain-of-Thought সংরক্ষণ ব্যবস্থা নয়। এটি মানুষের দৃশ্যমান গবেষণা-ইতিহাস, সিদ্ধান্ত, কাজের নির্দেশ, পরিবর্তন এবং প্রমাণের audit trail।

---

## ২. মূল চেইন

**চিন্তা → প্রশ্ন → উদ্দেশ্য → সিদ্ধান্ত → নির্দেশ → কাজ → পরিবর্তন → পরীক্ষা → ফলাফল → যাচাই → সংশোধন/অনুমোদন → পরবর্তী কাজ**

প্রয়োজনে চেইনটি আবার আগের ধাপে ফিরে যেতে পারবে। কোনো পুরোনো ধাপ মুছে ফেলা হবে না।

---

## ৩. প্রতিটি Chain Record-এর ন্যূনতম তথ্য

প্রতিটি গুরুত্বপূর্ণ কাজের জন্য একটি Chain ID থাকবে।

- Chain ID
- Parent Chain ID / কোন আগের কাজ থেকে এসেছে
- তারিখ ও সময়
- গবেষক/অভিনেতা
- ধরন: চিন্তা / প্রশ্ন / সিদ্ধান্ত / নির্দেশ / কাজ / পরীক্ষা / ফলাফল / সংশোধন
- কেন কাজটি করা হলো
- কী করতে বলা হয়েছিল
- কী করা হয়েছে
- কোন ফাইল/ডেটা/ইন্টারফেসে প্রভাব পড়েছে
- কোন version বা commit-এর সঙ্গে সম্পর্কিত
- পরীক্ষা কীভাবে করা হয়েছে
- পরীক্ষার ফলাফল
- প্রমাণ বা Evidence
- বর্তমান অবস্থা: OPEN / TESTING / VERIFIED / REJECTED / SUPERSEDED
- পরবর্তী Chain ID বা পরবর্তী কাজ
- প্রয়োজনীয় নোট

## ৪. Parent–Child সম্পর্ক

একটি নতুন কাজ আগের একটি চিন্তা বা সিদ্ধান্ত থেকে তৈরি হলে তার Parent Chain ID সংরক্ষণ করতে হবে।

উদাহরণ:

`THINK-0001`  → `QUESTION-0002` → `DECISION-0003` → `TASK-0004` → `TEST-0005`

এতে ভবিষ্যতে যে কেউ উল্টো দিক থেকেও অনুসরণ করতে পারবে:

**এই কাজ কেন হয়েছিল? → কোন সিদ্ধান্ত থেকে? → কোন প্রশ্ন থেকে? → কোন চিন্তা থেকে?**

---

## ৫. পরিবর্তনের ইতিহাস

কোনো গুরুত্বপূর্ণ ফাইল বা গবেষণা-তথ্য পরিবর্তন হলে:

1. আগের version-এর পরিচয় রাখতে হবে।
2. পরিবর্তনের কারণ লিখতে হবে।
3. কী পরিবর্তন হয়েছে তা লিখতে হবে।
4. পরীক্ষা করতে হবে।
5. Git commit/version সংরক্ষণ করতে হবে।
6. ভুল হলে আগের ইতিহাস মুছে ফেলা যাবে না। নতুন correction record তৈরি হবে।

## ৬. Database নিরাপত্তা

`quran_research.db` বা অন্য মূল গবেষণা data পরিবর্তনের ক্ষেত্রে Chain Record বাধ্যতামূলক হবে।

Database পরিবর্তনের আগে:

**Backup → Chain Record → Change → Validation → Commit → State Update**

Database পরিবর্তন না করেও website বা documentation-এর কাজ করা গেলে database স্পর্শ করা হবে না।

## ৭. AI-এর ভূমিকা

AI কাজের সহকারী হতে পারে, কিন্তু গবেষণার মালিক বা চূড়ান্ত কর্তৃপক্ষ নয়।

AI কোনো তথ্য তৈরি করলে তার উৎস/প্রমাণ এবং verification status আলাদা করে রাখতে হবে।

AI-এর অভ্যন্তরীণ গোপন reasoning সংরক্ষণ করা এই ব্যবস্থার উদ্দেশ্য নয়। সংরক্ষণ করা হবে দৃশ্যমান সিদ্ধান্ত, নির্দেশ, কাজ, ফলাফল ও প্রমাণ।

এক AI-এর কাজ অন্য AI ভবিষ্যতে পরীক্ষা করতে পারবে।

---

## ৮. গবেষকের অনুমোদন

যে কাজ গবেষণার মূল তথ্য, সিদ্ধান্ত বা প্রকাশিত দাবিকে প্রভাবিত করে, সেটি স্বয়ংক্রিয়ভাবে চূড়ান্ত ধরা যাবে না। প্রয়োজন অনুযায়ী মানুষের অনুমোদন বা যাচাই লাগবে।

বিশেষ করে:

- Source data
- Verified claim
- Translation Decision
- Database correction
- Public publication

এসবের ক্ষেত্রে স্পষ্ট status রাখতে হবে।

---

## ৯. Branching ও ভিন্ন মত

একটি প্রশ্নের একাধিক সম্ভাব্য উত্তর থাকলে আলাদা research branch তৈরি করা যাবে।

উদাহরণ:

`QUESTION-0010`

→ `ANALYSIS-0011A`  
→ `ANALYSIS-0011B`

কোনো branch অন্য branch-কে মুছে ফেলবে না। Evidence, uncertainty এবং disagreement পাশাপাশি থাকবে।

- Website-এর পরিবর্তনকে গবেষণার মূল data পরিবর্তনের সঙ্গে এক করে দেখা যাবে না।

## ১৩. ভবিষ্যৎ গবেষকের জন্য অর্থ

এই Chain System চালু হলে ভবিষ্যৎ গবেষক শুধু শেষ ফলাফল দেখবেন না। তিনি প্রয়োজনে দেখতে পারবেন:

**কোথা থেকে শুরু → কী প্রশ্ন উঠেছিল → কী সিদ্ধান্ত হয়েছিল → কী কাজ করা হয়েছিল → কী পরীক্ষা হয়েছিল → কোথায় ভুল হয়েছিল → কীভাবে সংশোধন হয়েছিল → এখন কোথায় এসে দাঁড়িয়েছে।**

এটাই প্রকল্পের গবেষণা-স্মৃতি।

## ১৪. জীবন্ত নিয়ম

এই নথি স্থির নয়। প্রকল্পের বাস্তব ব্যবহারে নতুন প্রয়োজন দেখা দিলে নিয়ম পরিবর্তন হতে পারে। কিন্তু পরিবর্তনের ইতিহাসও একই Chain System-এর মধ্যে সংরক্ষিত থাকবে।

**মূল নীতি:**

> কোনো গুরুত্বপূর্ণ চিন্তা যেন হারিয়ে না যায়, কোনো গুরুত্বপূর্ণ কাজ যেন তার কারণ হারিয়ে না ফেলে, এবং কোনো গুরুত্বপূর্ণ পরিবর্তন যেন তার ইতিহাস হারিয়ে না ফেলে।
