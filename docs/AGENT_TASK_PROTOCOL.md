# Agent Task Protocol — v1.0

## Command-to-Work Contract
User command → Task creation → Agent identity → governance inspection → project inspection → plan → isolated branch → minimal edit → test → repair loop → validation → review/approval → promotion → live smoke test → notification → handoff/close.

## Agent Intelligence Requirements
The Project Agent must:
- inspect before editing;
- use project instructions before target files;
- understand dependencies and protected assets;
- prefer minimal changes;
- distinguish facts, assumptions, and unknowns;
- keep raw research data untouched;
- use evidence for verification;
- self-correct after test failure;
- never claim live success without live evidence;
- preserve a complete work trail.

## Tool Expansion Roadmap
Future safe tools should cover:
- repository read/list/search
- branch/task management
- file edit
- build/test
- browser navigation
- DOM/visual inspection
- console inspection
- network inspection
- screenshot evidence
- deployment status
- live smoke test
- notification
- rollback

Production merge/deploy remains a separate approval-controlled capability.

## Context Memory
The agent must use Task ID, Agent ID, branch, handoff, and project governance records as persistent operational context. It must not store private chain-of-thought.
