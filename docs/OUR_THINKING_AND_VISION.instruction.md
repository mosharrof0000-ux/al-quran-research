## Purpose
Preserve the project's long-term philosophy, usability goals, research-partner model, AI independence, and future direction.

## Rules
1. Treat this as a living vision document, not an implementation checklist.
2. New ideas may be added, but existing decisions must not be silently removed or rewritten.
3. Separate vision/proposal from implemented functionality.
4. Do not turn aspirational statements into claims that a feature already exists.
5. Preserve user control, research independence, evidence-first principles, and non-destructive history.
6. Implementation details belong in the appropriate technical/status documents.

## Verification
When an idea becomes implemented, record implementation evidence in the relevant status/work/history file rather than falsely changing historical vision into completed status.
